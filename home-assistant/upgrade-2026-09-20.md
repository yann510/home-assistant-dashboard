# Home Assistant upgrade — September 20, 2026

## Baseline and recovery

Baseline: Core 2025.5.3, OS 17.1, Supervisor 2026.09.2 (already current),
Hilo 2026.3.6. Hilo was restored by reloading after a startup DNS failure;
the newer integration converts this class of failure to ConfigEntryNotReady
so Home Assistant retries setup.

Full backup `64361cc9` (`pre-upgrade-20260920`) includes Home Assistant,
all seven installed add-ons, share, SSL, and media. The unused addons/local
folder did not exist. A copy is saved off-device under the ignored local
investigation directory. Both copies have SHA-256:
`1fa21400ef8af17a4694e00d485b546d76743e5ebaaa3dd80d8ec4b99081eb97`.

Private baseline snapshots, configurations, logs, upstream release notes,
and the backup are in `.local/ha-upgrade-20260920/` (not committed).

Before upgrade, SmartThings and Tuya cloud had setup errors, Spotify was
retrying with a revoked refresh token, and Nginx Proxy Manager 0.12.3 was
in an error state with manual startup. The baseline records unavailable
entities to distinguish existing problems from upgrade regressions.

## Custom integration compatibility

Offline tests against Core 2026.9.3 exposed two House Mood incompatibilities:

- Target selection moved from `helpers.service` to `helpers.target` and now
  takes a `TargetSelection`. Use the new API with a fallback for 2025.5 rollback.
- The storage write hook no longer receives `path`. Forward the arguments
  supplied by the installed runtime while preserving failure propagation:
  journal write failures must still prevent device commands.

The existing tests reproduced both failures before the fixes. Test fixtures
also initialize the device registry explicitly on newer Home Assistant and
inject storage failure at the Store write boundary used by both versions.

Run the new offline environment with Python 3.14 and
`tests_ha/requirements-2026.9.txt`. The old compatibility requirements are
retained for rollback verification.

Pre-deployment validation:

- Core 2026.9.3: 25 HA tests pass; 37 attention tests pass; 125 backend tests
  run successfully (one existing optional skip).
- Core 2025.5.3: 25 HA tests and 37 attention tests pass.
- Two deployed House Mood files were backed up, checked against repository
  HEAD before overwrite, and downloaded again to verify matching SHA-256.
- The patched Lepro integration was preserved and backed up separately.

## Verification

- Home Assistant reports RUNNING on Core 2026.9.3. Configuration validation
  (`ha core check`) passed, including after the firmware reboot. MariaDB
  and the normally running apps started.
- Hilo loaded automatically after host reboot; gateway is on and all three
  thermostats are available, retaining 20°C targets. Live room readings were
  23°C office, 23.5°C gym, and 22°C bedroom.
- A simulated aiohttp DNS failure against the actual installed Hilo startup
  exception handler is unhandled in 2026.3.6 but becomes ConfigEntryNotReady
  in 2026.9.5. This verifies the retry handoff, without interrupting live DNS.
  It does not guarantee recovery from credentials or persistent upstream outages.
- SmartThings and Tuya cloud now load, recovering multiple appliance and
  light entities that were unavailable in the baseline.
- House Mood is idle, the attention sensor finishes startup with ready=true,
  and read-only Lepro native-state capture and Sonos queue services return
  HTTP 200 with their expected response structures.
- The production dashboard was verified in a browser: House Mood controls,
  live light states, speaker controls, weather, appliance cards, and all
  three thermostat cards render. A detected dryer completion reminder is shown;
  there is no Hilo gateway alert. No appliance cycles, heating changes, or
  whole-house mood changes were initiated for testing.
- Comparing the baseline with the post-OS snapshot found no newly unavailable
  existing entities except five restored Hilo gateway records. The integration
  exposes replacement gateway entities under its current naming convention;
  the dashboard resolves the active gateway correctly. Old records were preserved.
- All 28 automations retain their baseline enabled/disabled states.
- Independent review of compatibility changes against both HA versions found
  no blockers.

## Remaining limitations

Spotify still requires reauthentication (its refresh token was revoked before
this upgrade). Existing offline entities, including the washer and a bedroom
speaker entity, remain; upgrades cannot establish their physical connectivity.
The Lepro integration logs a d50 parsing error for its generic presentation,
but the preserved lossless native-state bridge successfully captures the device.
The pre-upgrade Supervisor unsupported flag referenced an additional
cors-anywhere Docker container. No unrelated container was removed. The
post-firmware-reboot resolution check reported no unsupported or unhealthy
conditions; Supervisor reports healthy=true and supported=true. It still
reports the detached Log Viewer app.

Nginx Proxy Manager 0.12.3 requires a separate migration: upstream v1.0.0
explicitly drops the old configuration. Its backup contains an existing
proxy-host configuration; do not overwrite it with a blind update.

The [Nginx Proxy Manager v1.0.0 release notes](https://github.com/hassio-addons/addon-nginx-proxy-manager/releases/tag/v1.0.0)
describe the destructive configuration transition. Its manual/error baseline
state was preserved at 0.12.3 rather than deleting the existing configuration.
